# 业务规则

本文件记录第一版实际执行的统计口径。配置项位于 `config/pilot2.toml` 的 `[rules]`。

## 事件识别

支持中英文录像开启和关闭：

- `通道N 主存储器主码流录像开启`
- `ChannelN Main record on`
- `通道N 主存储器主码流录像关闭`
- `ChannelN Main record off`

支持 ACC 断电、低压断电和开机原因记录。同一日期、时间和消息的重复行只保留一次。

## 时间轴

日志行只有时分秒，日期来自文件名前缀 `YYYYMMDD`。文件名无有效日期时尝试从带日期的消息中提取，否则跳过并记录警告。

时间轴按文件日期和文件内原始行顺序构建。普通时钟回退通过累计偏移修正，使后续录像时长保持连续；原始时间保存在事件模型中用于追溯。

`Adjust time` 和配置保存行不更新时间轴锚点，避免把配置引发的时区切换误判为录像中断。

## 通道状态与关闭

- 断电事件发生后，仍开启的通道进入 pending 状态。
- 5 秒内出现显式关闭时，使用显式关闭时间。
- 超过 5 秒没有显式关闭时，使用断电时间 +5 秒关闭。
- 后续延迟上报的关闭不会延长录像。
- 日志结束时仍开启的通道截断到统计窗口末尾，并标记为悬空段。
- “当前已录制时长”不包含日志末尾悬空段。

5 秒阈值配置为 `implicit_close_seconds`。

## 跨天与孤立关闭

`cross_day_rollback_seconds` 只用于分类跨天或大跨度回退。

`orphan_close_max_seconds` 只用于孤立关闭，不再与跨天逻辑共用同一个变量。

日初没有录像开启事件、但出现明确关闭事件时，第一版从当天首个可观测事件补算，避免把缺失日志期错误计入录像。

## 擦写计数

- 首次 `avgEraseCount` 观测作为起始值。
- 只有计数值增加才产生擦写事件。
- 一次从 0 增至 5 记一次擦写，同时标记“异常跳变 +5”。
- 计数回落记录为采样异常，不产生擦写，也不降低后续比较基准。
- 擦写时间使用首次观测时间，不代表 eMMC 实际擦除的精确时刻。

## 异常段

- 连续录像超过 24 小时且跨过缺失日志日：标记幽灵段。
- 单段内相邻事件最大间隔超过 4 小时：标记疑似挂机或空转。
- 末尾未关闭：标记悬空段。
- 时钟回退、计数回落和异常跳变在设备页列出。

异常标记默认不修改录像时长，避免把存疑数据直接归零。

## 历史兼容口径

现有报告是行为基线。以下设备存在必须显式配置的历史行为：

| 设备 | 配置 | 原因 |
|---|---|---|
| 设备03 | `pre_erase_duration` | 首次擦写前包含日志窗口之前的连续录像 |
| 设备03 | `compensate_clock_rollbacks = false` | 旧报告不把 10-20 的校时调整换算成额外录像时长 |
| 设备07 | `reset_active_at_day_start` | 旧报告按日切分跨天开启状态 |
| 设备07 | `low_voltage_stops_recording = false` | 旧报告未把低压关机作为录像关闭事件 |
| 设备07 | `exclude_day_end_from_current = true` | 旧报告不把日末开启段计入当前已录制时长 |

这些兼容项只对指定设备生效，新设备默认使用当前业务规则。
